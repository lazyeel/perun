# `session16`: measured KDF structure (2026-11-22)

## Status and evidence boundary

This note records the independently reproducible measurements for the Android
`ProvisioningStart` `session16` producer. Sections 1–8 preserve the investigation
as it stood before the final closure in § 9; their open-item statements are
historical, not the current status. The planter closure at `cfa5f51` is separate.

**Current-status update (final on 2026-11-22):** § 9 supersedes the earlier open
items. `session16_from_entropy([u8;40]) -> [u8;16]` is now implemented in pure
Rust and matches all twelve distinct controlled native inputs byte-for-byte,
including held-out `0x11`/`0x22`, both predecessor lengths and a session output
that requires seventeen stores. Committed tests carry hashes only; a separate
env-gated test checks the private CPIM bytes. This closes `session16` itself, not
the remaining CPIM, End, OTP or integration tracks.

Private checkpoints, controlled inputs, register snapshots and CPIM values stay
in mode-`0700` directories under `target/private-cores` (with compatibility
symlinks in `/tmp/opencode`); private files are `0600`. This report contains only
RVAs, algorithm constants, sizes, counts and hashes. No raw seed, `R14`, session
block, key buffer or CPIM bytes are included.

Controlled native runs replace only the 40-byte `/dev/urandom` read. Both
established vectors used here were reproduced exactly:

* `0xA5` repeated 40 times;
* bytes `00,01,...,27` (40 sequential bytes).

The sequential vector is useful because the raw draw cannot be confused with a
constant-filled generated buffer.

## 1. Stage attribution

Same-run checkpoints establish:

| boundary | `session16` present verbatim | digest present |
|---|---|---|
| Start entry, `libstoreservicescore+0x1D3010` | no | no |
| transform entry, `libCoreADI+0x87554` | no | no |
| planter entry, `libCoreADI+0xDD511` | yes | no |

The session block is present at `RBP-0x44D0` and at a heap copy by `0xDD511`.
The 16-byte final store loop is at `0xA5CCE..0xA5D3C`, with the actual one-byte
store at `0xA5CF6`. Addresses descend from `slot+0x0F` to `slot`. A checkpoint
must be filtered by that first destination: the same PC also writes other
16-byte fields. An unfiltered checkpoint at the first `0xA5CCE` hit, and a filter
for `slot` instead of `slot+0x0F`, select the wrong loop or only its last store.

## 2. The isolated output loop

Replaying from the correctly filtered first-destination checkpoint through the
16th store gives an exact match with the native CPIM session block. The measured
path is 83,566 instructions with only **457 unique PCs**:

* a 46-instruction short path between output stores;
* a 27,667-instruction CFF/arithmetic body, executed four times with an
  identical PC stream, before the long-path outputs;
* two small internal arithmetic helpers at `0x59100` and `0x182400`, not libc.

Two independent sessions have identical PC streams and identical first-read
address sets. The output-rooted census found:

* 32 first-read frame bytes, identical across the sessions;
* zero heap reads and zero reads from other libraries;
* 2,620 first-read bytes in `libCoreADI`, with 2,484 differing in its mutable
  `.data` (the generated region is at `0x183090..0x183A4F`);
* only `R14` differs among entry registers; it is not the public 32-bit session
  handle.

Transplanting both the mutable data page and `R14` transfers the exact session
output in both directions. The page alone is insufficient. This is the complete
input boundary of the isolated loop, but not yet a raw-entropy-to-session API.

An attempted replay from the much earlier transform entry is not autonomous:
it reaches external/libc paths and does not reproduce the session. A semantic
`arc4random` return stub alone does not repair that long replay. The correctly
filtered native checkpoint is therefore the authoritative boundary for the
loop measurements above.

## 3. The 40-byte seed enters through Bionic `arc4random`

The indirect seed target is Bionic `arc4random` at libc RVA `0x5F3F0`. Its
initialization performs `getentropy(..., 0x28)`, matching the independently
measured 40-byte draw. The matching Android 5.1 Bionic source uses:

1. a 32-byte ChaCha key and an 8-byte IV from the draw;
2. ChaCha20 with a zero initial counter and the standard 20 rounds;
3. a 1,024-byte keystream buffer, reinitializing from its first 40 bytes;
4. output beginning at buffer offset 40, as little-endian `u32` words.

For the sequential controlled draw, the measured initial return and the next
three `R12` calls equal exactly the first four words of that stream at offsets
`40,44,48,52`. This validates the ChaCha implementation and output position,
not a digest of the draw.

The first returned word also produces the MT initializer seed through the
measured mask at `0x87BAC`:

```text
seed = (out0 - ((2*out0) & 0x79cdc552) + 0x3ce6e2a9) mod 2^32
```

The final four-word key buffer used by the first mixing loop is measured
directly at `0x87CF0`. Its first three words are produced by the other measured
mask:

```text
masked(x) = (x - ((2*x) & 0xc34d0ed8) + 0x61a6876c) mod 2^32
```

The fourth slot takes a separate path. **The general construction of that
fourth slot is still open.** Consequently, the initialization below is fully
validated on the sequential vector, but is not yet claimed complete for every
possible draw. Plain MD5/SHA/SHA-3/BLAKE digests, direct `init_by_array`, and
plain C++ `seed_seq` did not reproduce the native state.

## 4. The generator is MT19937-shaped, with native MBA seed/twist code

The generator has a 624-word state at `libCoreADI+0x183090` (2,496 bytes).
The tempering code at `0xA683B..0xA68C8` initially appeared to reduce to textbook
MT19937 shifts (shown below). Full output comparison later falsified that
simplification: the executed MBA terms and final XOR in § 9 are required.

```text
y ^= y >> 11
y ^= (y << 7)  & 0x9d2c5680
y ^= (y << 15) & 0xefc60000
y ^= y >> 18
```

At the session loop, the state cursor is after 32 generated words. The native
seed schedule is not the textbook `init_genrand`/`init_by_array` sequence: the
masks in the following subsections are required and have been checked against
native state snapshots.

### 4.1 Initial recurrence: exact on all 624 words

Let `K = 0x3ce6e2a9`, `mt[0] = seed`, and for `i = 1..623`:

```text
p       = mt[i-1]
rax     = 0x6d3532 + i - 1
mixed   = (((p >> 30) - ((p >> 29) & 2) + K) mod 2^32) XOR p
product = 1812433253 * mixed mod 2^32
a       = (rax + product) mod 2^32
b       = (a + 0xff92cacf) mod 2^32
d       = (2*a + 0xff25959e) & 0x79cdc552
mt[i]   = (b - d + K) mod 2^32
```

This reproduces **624/624** words at `0x87C80`.

### 4.2 First mixing loop: exact formula and buffer update

The first loop has 624 iterations and carries `i` with the native index-624
wrap. Let `buffer` be the measured four-word key buffer. For `k = 0..623`:

```text
p       = mt[i-1]
j       = k % 4
x       = (((p >> 30) - ((p >> 29) & 2) + K) mod 2^32) XOR p
c       = 1664525 * x mod 2^32
d       = (0x32cc1a * x) & 0x79cdc552
c       = (c - d + K) mod 2^32
c       = c XOR mt[i]
rax     = 0x12bd5cdd + j
s       = 0x61a6876c XOR buffer[j]
y       = (s + rax + 0xed42a323 + c) mod 2^32
c2      = (2*y) & 0x79cdc552
mt[i]   = (y - c2 + K) mod 2^32

buffer[(k+1) % 4] ^= 0xf7803080, if (k+1) % 4 == 0
buffer[(k+1) % 4] ^= 0xf7803081, otherwise

i += 1
if i >= 624:
    mt[0] = mt[623]
    i = 1
```

Every one of the first 50 iteration snapshots matches, and the final state
matches before the following loop. The low-bit distinction in the buffer-0 mask
is required; using `0xf7803081` for all four words fails at iteration 5.

### 4.3 Second mixing loop: preserve `i = 2` from the first loop

The second loop has 623 iterations. It starts at `i = 2`, carried from the first
loop's wrap, not reset to 1:

```text
repeat 623 times:
    p   = mt[i-1]
    x   = (((p >> 30) - ((p >> 29) & 2) + K) mod 2^32) XOR p
    c   = 1566083941 * x mod 2^32
    d   = (0xbab116ca * x) & 0x79cdc552
    c   = (c - d + K) mod 2^32
    c   = c XOR mt[i]
    c   = (c - i) mod 2^32
    d2  = (2*c) & 0x79cdc552
    mt[i] = (c - d2 + K) mod 2^32
    i += 1
    if i >= 624:
        mt[0] = mt[623]
        i = 1
```

All 50 captured iteration snapshots match. The 623rd final state matches 623 of
624 words; only the value of `mt[0]` differs if a textbook final marker is
applied prematurely. Before the twist, native code does carry `0x80000000` in
`RBX`, so the marker is real but must be applied at the correct stage.

## 5. What remains open

The **twist/output stage is not closed**. Standard MT19937 twisting from the
measured initialized state does not reproduce `R14` at output 32 or the native
post-twist state. The remaining work is to transcribe the exact twist MBA at
`0xA65F9..0xA6810` and then re-run the complete `draw[40] -> session16` check.

In addition, the general formula for the fourth key-buffer slot must be
transcribed and checked on at least `0xA5`, sequential, `0x11` and `0x22` draws.
Until those two items are complete, there is deliberately no `session16.rs` and
no autonomous CPIM claim.

The successful smaller result is real: the isolated final 16-store loop is
self-contained and byte-exact, and its complete input is the generated MT page
plus `R14`. The entropy-side work has now identified the exact ChaCha input and
all three initialization/mixing recurrences; it has not yet been joined into a
production function.

## 7. Twist closure on the sequential vector, output replay still open

Further native checkpoints after the original note have closed a substantial part
of the twist, but not the complete `session16` function.

### Proven

Starting with the actual pre-twist 624-word state, the measured twist now
reproduces the native post-twist state at `0xA6831` **on all 624 words**. The
first 227 stores and all 396 stores in the second loop match the live trace
individually; the special final store also matches. This is a complete state
comparison, not just a few selected outputs.

Important exact semantics that caused earlier failed models:

* `RBX` in the first loop is the upper mask `mt[i] & 0x80000000`, not the whole
  previous state word.
* The matrix is the native pair from the frame, not `0x9908b0df`: slot zero is
  `0x4e79914b`, slot one is `0xd7712194`.
* The second loop reads `mt[i+1]` first and `mt[i+397]` second. At `i=227`,
  `mt[397]` is the updated `mt[0]` from the first loop, not the old initial
  value.
* The last `y` chain at `0xA67AA` needs executed-path measurement, not a linear
  CFF reading. The earlier claim that `add edi,esi` at `0xA67D3` was junk is
  withdrawn: the closing replay executes it. Its exact position in the general
  final-word formula is given in § 9.
* At `0xA6845` and `0xA6870` the executed opcodes are **XOR**, not AND. The
  shifts are performed first and XOR follows; there is no pre-mask. These two
  corrections make the final temper `EDX` match native exactly at `0xA68C8`.

### Not yet proven

The full-state twist result above is currently validated on the sequential
`00..27` draw. A held-out draw must still verify the final-word matrix parity
and the `y` chain's index-state constant. `R14` after the output XOR is not yet
byte-reproduced at the session-loop checkpoint from the same replay, so the
`session16` output gate remains open. The fourth key-buffer slot also remains
open as described in § 5.

The current work is therefore output/replay reconciliation: compare the exact
Unicorn replay against its own native run, identify the generator cursor and
remaining CFF-state transition, and only then implement the production function.
There is still no `session16.rs`, no CPIM autonomy claim, and no new production
commit beyond the documentation commits already published.

## 8. Key construction and complete native output replay closed

The fourth key-buffer slot is no longer open. Both controlled draws establish the
same five-output construction, with `masked` as defined in § 3:

```text
seed = seed_mask(out0)
key  = [masked(out4), masked(out2), masked(out3), masked(out1)]
```

Thus the fourth slot is `masked(out1)`, not a digest, raw entropy slice or another
native return. The seed/key formulas and the first five ChaCha output words are
implemented in dependency-free Rust as `session::mt_seed_and_key`. The module also
implements the measured 1,024-byte `arc4random` stream (984 exposed bytes after
offset 40), supports both the native 64-bit-IV and RFC 96-bit-nonce ChaCha layouts,
and has an RFC 8439 block test plus sequential/`0xA5` hash-only goldens. It does
not expose secret values through `Debug` and has no production oracle dependency.
This is an entropy/key component only, not the promised complete `session16` API.

The invocation-boundary error in earlier output comparisons is also resolved. The
correct native twist-address counts for the controlled runs are **7,264** for
sequential and **7,037** for `0xA5`; these are measured path-specific hit counts,
not algorithm constants. Starting at the resulting `0xA65F9` checkpoint and
replaying through the correctly filtered sixteen stores gives:

| controlled draw | dynamic instructions | unique PCs | sixteen-byte result |
|---|---:|---:|---|
| sequential | 102,025 | 457 | exact native match |
| `0xA5` | 102,025 | 457 | exact native match |

This closes the native replay/output reconciliation that § 7 left open. It does
**not** by itself prove the compact Python/Rust formula from raw entropy: that
formula must still reproduce the same state transitions and outputs without the
captured checkpoint. In particular, a first twist is exact but naively applying
the current compact twist twice is not idempotent with the native second entry;
the native second entry differs from the first post-twist result in the final
word. Final-word matrix selection and `y`/index-state therefore remain explicit
formula gates.

### Current implementation gate

2. Validate matrix parity, cursor state and all sixteen bytes on held-out `0x11`
   and `0x22` draws.
3. Add `session16_from_entropy([u8;40]) -> [u8;16]`, private byte-parity tests and
   committed hash-only goldens only after those checks pass.

No complete `session16` or autonomous CPIM claim is made yet.

## 9. Full raw-entropy producer closed in pure Rust

The statement immediately above is historical. The complete producer is now
implemented as `session::session16_from_entropy([u8;40]) -> [u8;16]`. The earlier
102,025-instruction replay was only the correctly selected **tail** beginning at
first-half iteration 226; it was not an end-to-end formula. The compact model
below has since been checked from the raw draw itself.

### 9.1 The first twist family and all 32 rounds

After the two initialization mixes, the first family starts with marker
`mt[0] = 0xbce6e2a9`. Its in-place round is shared by all 624 positions, including
the last one:

```text
next   = mt[(i+1) % 624]
y      = (mt[i] & 0x80000000) | (next & 0x7ffffffe)
a      = (y >> 1) XOR 0x1e737154
a      = a - ((2*a) & 0x79cdc552) + 0x3ce6e2a9  (mod 2^32)
matrix = [0x5bb8223a, 0xc2b092e5][(~next) & 1]
mt[i]  = mt[(i+397) % 624] XOR matrix XOR a XOR 0x675ec093
```

The formula matches 227/227 first-half stores, 396/396 second-half stores and the
last word. Applied repeatedly from the entropy-derived initialization, it matches
the native next-round state on **all 624 words for every one of 32 consecutive
rounds**. The state after round 32 is exactly the first `0xA65F9` input. This
retires the earlier comparison that incorrectly applied the second family
directly to the initialization mix.

### 9.2 The `0xA65F9` family is idempotent too

The first two loops in § 7 retain their measured formulas. Across 26 fully
captured consecutive transitions they reproduce the first 623 words on every
round; the final-word reconciliation then gives 624/624 on every transition.
The general last-word rules are:

* `final_upper` is the old `mt[623] & 0x80000000`, saved before the loops;
* matrix parity is `(~mt[0]) & 1` using the **new** `mt[0]` after the first loop;
* `0xA67D3` (`add edi,esi`) executes. `EBX` is formed from the old `EDI+ESI`
  first; `EDI` is then updated before the later correction term. Omitting the
  add, or applying it before forming `EBX`, selects the wrong state;
* the alternative values of the apparent external `RCX/RDX` state are therefore
  not extra inputs. They reduce to new-word parity and old-final-word upper bit.

The compact final states also match the native session checkpoints on sequential
and `0xA5`. The final state SHA-256 for the fourth `0xA5` session word is
`042e6caa44d26abd3a5abfa34b148a33c2eafd4ba1912e934b0cbdf30be8f6fb`, identical
in native replay and compact evaluation.

### 9.3 Temper and output words

The earlier textbook-temper simplification is withdrawn. The executed chain has
the MT shifts but also MBA corrections at `0xA6845..0xA68A5` and a final
`XOR 0xe46af5c7`; `perun-adi-core/src/session.rs::temper` is the exact 32-bit
formula and was checked against native `EDX/R14` at `0xA68C8`. Each output word
then uses:

```text
word = native_temper(mt[cursor]) XOR 0x6ae8e6c8
```

The cursor starts at 32, increments once per twist/output and wraps to zero when
its old value exceeds 623. A session byte at shift `s in {0,8,16,24}` is:

```text
x    = (word XOR 0x3063cfe3) >> s
byte = low8(x - 2*(x & 0x56) + 0x56) XOR 0x34
```

### 9.4 The 120-byte predecessor determines the twist count

The `A65F9` address counts are now explained rather than supplied to the model.
Before session16, the same output-word/byte rules fill a **120-byte** predecessor.
A zero transformed byte is written but does not advance the destination;
therefore:

```text
N = number_of_output_words_needed_for_120_nonzero_advances + 1
```

The first session word is round `N`. With no predecessor zero, 30 words suffice
and `N=31`; one zero makes `N=32`. This compact prediction matches every measured
counter: sequential, `0x01` and `0x7f` have one predecessor zero and `N=32`;
`0xA5`, `0x11`, `0x22`, `0x33`, `0x44`, `0x55`, `0x80`, `0xff` and reverse
sequential have none and `N=31`. Thus the earlier `7,264=32*227` and
`7,037=31*227` counts are outputs of the algorithm, not invocation constants.

Session output uses the same nonzero-advance rule, writing backwards from byte
15 and returning immediately after a nonzero store at byte zero. Usually this is
16 stores/four words. The reverse-sequential vector has a zero transformed byte,
so the destination does not advance, the next word overwrites that transient
zero, and completion takes **17 stores/five words**. A fixed sixteen-store loop
is not general; the production loop implements the pointer rule.

### 9.5 Implementation and verification boundary

`crates/perun-adi-core/src/session.rs` now contains dependency-free Rust for the
complete draw-to-session path. It has no Apple machine code, ELF/Bionic image,
capture read, file I/O or native subprocess. Twelve controlled native inputs are
committed as SHA-256-only unit goldens. The separate
`tests/session16_corpus.rs` gate is enabled by `PERUN_SESSION16_DIR` and compares
full bytes against private `cap/cpim.bin` without printing expected values.

Verification results:

* **12/12 distinct inputs** match native session16 byte-for-byte;
* **13/13 captures** match in the extended development matrix (the reverse draw
  was independently repeated);
* held-out `0x11` and `0x22` both match;
* both `N=31` and `N=32`, and both 16- and 17-store session outputs, match;
* private Rust gate: 12/12; public hash-only gate: 12/12;
* workspace tests and workspace Clippy with `-D warnings`: green.

This is closure of the **session16 component only**. `OracleCaptureInputs` and
CPIM assembly have not yet been rewired to consume it, so autonomous CPIM is
still not claimed. The next Track-C items remain WeaveFeeds, mixer-14 and the
eight digest-word producers, followed by integration; independent OTP, Rust
`ProvisioningEnd` and clean-environment Track-D acceptance remain separate.
